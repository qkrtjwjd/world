# 무채색 낙원 시나리오 → Yarn 변환 스킬

시나리오 정본 `.docx` 를 Yarn Spinner `.yarn` 스크립트로 변환한다.
변환 규칙은 `references/명세서.md`(v9), 실제 변환은 `scripts/scenario_parser.py`(v3)가 수행한다.

## v3 — 화이트리스트 방식 (2026-08-09 교체)

v2 는 **폴스루 블랙리스트**였다. 마커·대사 패턴을 순서대로 시도하다 아무것도 안 걸리면
그 줄을 나레이션으로 그대로 출력했다. 그래서 `▶` 마커가 떨어진 연출 지시가 대사로
플레이어에게 표시됐고(`Scenario/확인필요.md` 7-3), `※` `【 】` `S#xx` `·` 는 아예 인식조차 못 했다.

v3 은 **화이트리스트**다. 통과시킬 4종만 정의하고 나머지는 전부 차단한다.
판정 실패는 조용히 새는 대신 `// UNCLASSIFIED` 로 드러난다. 조용히 새는 경로가 없다.

## 언제 이 스킬을 쓰는가

- 정본이 개정되어 .yarn 을 다시 뽑아야 할 때
- 씬이 추가되어 노드 매핑을 늘려야 할 때
- 변환 규칙을 확인해야 할 때

## 작업 순서

1. **명세서를 먼저 읽는다.** `references/명세서.md` 를 처음부터 끝까지. 추측하지 말 것.
2. **`Scenario/node_map.json` 을 확인한다.** 씬 → 노드 매핑, 씬별 대사 수, 화자별 배분이 여기 있다.
   정본이 개정돼 대사 수가 바뀌었으면 **여기를 먼저 고친다.** 안 고치면 게이트가 막는다.
   단 **D 에 실제로 들어간 뒤에** 고친다 — 승인만 된 미반영 사항으로 미리 올리지 않는다.
3. **파서를 실행한다.** 정본은 항상 같은 문서이므로 경로를 적지 않는다.
   ```
   python .claude/skills/muchaesaek-scenario-to-yarn/scripts/scenario_parser.py
   ```
   기본 정본은 `scenario_parser.py` 의 `DEFAULT_DOCX` 다:
   `C:\Users\ThinkPlant\Desktop\낙원\files (1)\D_무채색_낙원_시나리오_정본.docx`
   (저장소 밖 Desktop 에 있다. 다른 문서를 쓸 때만 `.docx` 경로를 인자로 준다.)
   출력 기본값은 `Scenario/output_v3/`.
   (v2 산출물이 있던 `Scenario/output/` 은 2026-08-14 정리로 삭제됐다. 다시 만들지 말 것.)
4. **게이트를 확인한다.** `gate_report.txt` 가 FAIL 이면 종료 코드 1이다. 산출물을 쓰지 말 것.
5. **`unclassified.txt` 를 눈으로 확인한다.** 문서 제목·섹션 헤더·에셋 목록만 있어야 정상이다.
   현재 D 에는 이탤릭이 빠진 지문 1줄(`세라의 표정이 살짝 어두워진다.`)이 있고,
   **그것이 여기 잡히는 것이 정상이다.**
   **여기에 대사가 섞여 있으면 규칙 버그다.**
6. **`diff_vs_current.txt` 로 현행 대비 변화를 사용자에게 보여주고 확인받는다.**

## 통과시키는 4종 — 이 외에는 전부 차단

| # | 대상 | 판정 |
|---|---|---|
| ① | 화자 대사 | 첫 run 볼드 + 허용 화자 8종 + 잔여가 따옴표로 시작 |
| ② | 루 독백 | 문단 전체 이탤릭 + `(루): '...'` **또는** 첫 run 볼드 + `루 (속으로) "..."` |
| ③ | 쪽지 텍스트 | `node_map.json` 의 `note_scene`(S#04D) 안의 무서식 줄. **대화창이 아니라 전용 UI** |
| ④ | 나레이션 | `node_map.json` 의 `narration_whitelist` 에 등재된 것만 |

허용 화자 8종
- 집 구간 D-1: **세라 · 쿠루 · 부엉이 · 루 · 라디오(유)**
- 마을 구간 D-2: **솔 · 미루 · 아모**
- `루` → `{$이름}` / `{이름조사("가")}` 로 후처리 (`tools/rename_lu_in_yarn.py` 재사용)
- `라디오(유)` → 화자 ID `radio_yu`, 표시명 `라디오`, 포트레이트 없음
- 루 독백 → 화자 ID `루독백`, 표시명 빈 문자열, 포트레이트 없음
- 표시명·포트레이트 규약의 문서상 단일 출처는 `node_map.json` 의 `speaker_display` 다.
  실동작은 `scenario_parser.py` 의 `SPEAKERS` 상수이므로 **둘을 함께 고쳐야 한다.**

## 차단되는 것

- **이탤릭 지문 전체** — 텍스트로 띄우지 않고 연출로만 처리한다
- `[FILTER]` `[BGM]` `[SFX]` `[UI]` `[CAM]` `[TRIGGER]` `[목표]` `[상호작용]` `[분기]` → `*_staging.json` 으로 분리. 텍스트 아님
  - `[분기]` 는 D-3 S#20 에서 들어온 표기다 (`[분기] 인형화 0~30` / `31+` / `공통`).
    대사 묶음의 경계이므로 차단하지 않고 staging 으로 뺀다 — 차단하면 어느 줄이 어느 분기인지가 사라진다
- `▶` 로 시작하는 모든 줄 — **볼드 여부 무관.** 판정이 서식에 의존하지 않게 하기 위함이다.
  현재 D 에는 볼드가 빠진 `▶` 줄이 10건 있고, 서식에 의존하면 그때 샌다
- `※` 로 시작하는 모든 줄 (집필 주석)
- `·` 로 시작하는 에셋 목록
- 씬 헤더 `【 】` 및 `S#xx` 줄
- 구간 표제 `D-1.` `D-2.` `D-3.` … — 정규식 `^D-\d+\.` 로 판정한다. **번호 하드코딩 금지**
  (CLAUDE.md §6 의 `^\*\*D-\d+\.` 는 마크다운 표기. docx 본문에는 `**` 가 없고 볼드는 run 속성이다)

## 절대 규칙

- **노드 이름은 `node_map.json` 이 정한다.** 파서가 추측하지 않는다.
  이름은 C# 인스펙터 필드에 직렬화돼 있으므로 바꾸면 유니티 재배선이 필요하다.
  마을 구간의 기존 배선 노드 4개는 `node_map.json` 의 S#14·S#15 `_note` 참조.
- **정본 1씬이 여러 노드로 쪼개진 것은 의도적이다.** NightSequenceManager / KitchenTriggerCutscene
  이 노드 사이에 클로즈업·무음 연출을 끼워넣는다. 임의로 합치지 말 것.
- **BGM/SFX/커맨드 이름을 지어내지 않는다.** 실제 등록된 커맨드로 안전하게 매핑되지 않으면
  `staging.json` 에 `command: null` + `todo` 로 남긴다.
- **판정 실패 줄을 버리지 않는다.** `// UNCLASSIFIED` 로 남긴다.
- **파서는 시나리오를 창작/각색하지 않는다.**
- **산출물을 `Assets/Dialogue` 에 자동으로 덮어쓰지 않는다.** 거기엔 수동 보정 레이어가 얹혀 있다
  (색상 마크업, 연출 커맨드, SFX 주석). 반영은 사람이 diff 를 보고 결정한다.
- **현행 yarn 에만 있고 정본에 없어 차단된 대사는 삭제하기 전에 사람에게 정본 승격 여부를 묻는다.**
  차단은 규칙이 동작한 것이지 그 줄이 불필요하다는 뜻이 아니다.
  (실례: S#07 의 루 독백 2줄은 수기 작성분이라 차단돼 있다. 승격은 **승인됐지만 D 에 아직 반영되지 않았다** —
  그래서 기대값은 여전히 0 이고, 그 2줄도 지우지 않는다.)
- **게이트 기대값을 산출 결과에 맞춰 고치지 않는다.** 숫자가 어긋나면 원인을 찾는 것이 먼저다.
  기대값 변경은 사람의 승인을 받는다.

## 산출물

| 파일 | 내용 |
|---|---|
| `<stem>.yarn` | 노드별 표시 텍스트 레이어 + UNCLASSIFIED 주석. **연출 커맨드는 없다**<br>**서식 태그(`<i>`, `<color=`)도 넣지 않는다** — 이탤릭·색상은 Dialogue Runner 가 화자 ID 기준으로 런타임에 적용한다 (`node_map.json` 의 `speaker_display`) |
| `<stem>_staging.json` | 연출 데이터([FILTER]/[BGM]/[SFX]/[UI]/[CAM]/[TRIGGER]) + 화자 테이블 |
| `notes.json` | 읽는 물건 텍스트 (전용 UI 용) |
| `unclassified.txt` | 판정 실패 전체 목록 |
| `diff_vs_current.txt` | 현행 `Assets/Dialogue` 대비 표시 텍스트 diff |
| `gate_report.txt` | 검증 게이트. FAIL 이면 종료 코드 1 |

## 검증 게이트

`node_map.json` 과 어긋나면 **exit 1**:

**4중 대조.** 하나라도 틀리면 exit 1.

| # | 검사 | 잡는 것 |
|---|---|---|
| 1 | 씬별 합계 == `expected` | 누락·중복 |
| 2 | **화자별 배분 == `by_speaker`** | 합계는 맞는데 화자가 밀린 경우 |
| 3 | 노드별 대사 수 == `count` | 씬 안에서 노드 간 배분이 밀린 경우 |
| 4 | 노드 **앵커 텍스트** 일치 | 카운트가 전부 맞는데 내용이 어긋난 경우 |

부가: 합계 == `expected_totals` / `node_map` 에 없는 씬에서 통과 항목이 나오면 실패.

**`by_speaker` 는 전 씬 필수다.** 미등재도 실패다 — 데이터만 있고 파서가 읽지 않는 상태를 두지 않는다.
`루독백` 은 별도 화자로 계상한다. 실패 시 화자별 차이와 방향(+/-)을 찍는다:

```
FAIL S#04C  세라: 기대 10 / 산출 11  (+1)
            쿠루: 기대 14 / 산출 13  (-1)
```

**기대 합계 — D 실측 85**

| 구간 | 화자대사 | 루독백 | 쪽지 | 나레이션 | 소계 |
|---|---|---|---|---|---|
| D-1 집 (S#01~S#13) | 59 | 2 | 2 | 1 | **64** |
| D-2 마을 (S#14~S#15) | 19 | 2 | — | — | **21** |
| **데모 총계** | 78 | 4 | 2 | 1 | **85** |

⚠ `node_map.json` 의 `dialogue` 값은 **82** (78+4). 파서가 루 독백을 `dialogue` 에 합산한다.
⚠ **승인만 됐고 D 에 없는 사항으로 기대값을 미리 올리지 않는다** (CLAUDE.md §9-1).
S#07 승격 2줄은 승인됐지만 D 에 없어 기대값은 **0** 이다.
D-3 숲 구간(S#16~S#20)은 원고 미작성이라 `node_map` 에 없다.

`UNCLASSIFIED` 건수는 실패 조건이 아니다. 리포트에 적고 사람이 판단한다.

## 이름의 출처 — 목록을 문서에 복사하지 않는다 (CLAUDE.md §4)

이름은 코드가 바뀌면 같이 바뀐다. **작업 시점에 코드에서 직접 조회한다.**

| 대상 | 출처 |
|---|---|
| Yarn 커맨드 | `[YarnCommand("…")]` 어트리뷰트 + `AddCommandHandler("…")` 등록 (`Assets/Scripts/Dialogue/YarnCommandBridge.cs` 등) |
| 스프라이트 감정 ID | `Assets/Date/Dialogue/CharacterSpriteData.asset` 의 `emotionId` |
| 포트레이트 설정 | `Assets/Resources/PortraitConfigs/*.asset` |
| SFX | AudioManager 등록 목록 |

BGM 경로 형식만 고정이다: `Resources.Load("BGM/파일명")`.

> 목록을 문서에 박아두면 개명 때 반드시 어긋나고, **규약을 따를수록 틀리게 된다.**
> 실제로 여기 `open_merchant_ui` 가 남아 있었다 (현재 이름 `open_sol_trade`).
>
> **파서는 커맨드 이름을 만들어내지 않는다.** `[TRIGGER]` 는 매핑이 확실하지 않으면
> `staging.json` 에 `command: null` + `todo` 로 남긴다. 그래서 이 목록이 애초에 필요 없다.

## 기술 참고

- v3 은 **Claude API 를 쓰지 않는다.** 규칙만으로 판정하고, 애매하면 UNCLASSIFIED 로 남긴다.
  `anthropic` 라이브러리도 `ANTHROPIC_API_KEY` 도 필요 없다.
- 입력은 `.docx` 다. 볼드·이탤릭이 화이트리스트의 판정 근거인데 그 정보는 docx 에만 있다.
  `word/document.xml` 을 직접 읽으며, 외부 라이브러리 없이 표준 `zipfile` + 정규식으로 처리한다.
- `Scenario/House_*.txt` (v2 의 손질된 중간 파일)는 이제 파이프라인에 쓰이지 않는다.
  다만 거기 담긴 수기 결정(폐기 대사, SFX 이름)은 참고 자료로 남아 있다.
