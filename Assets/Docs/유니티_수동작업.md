### 1-C. PostProcessingController 씬 배치 🔴 (20분)

#### 현재 상태

`PostProcessingController`는 일반 씬 컴포넌트입니다 (`DontDestroyOnLoad` 아님).

> 🔎 **2026-08-25 실측 — "MapScene 에만 있다"는 아래 기술은 틀렸습니다.**
> 이 컴포넌트는 **`Assets/Prefabs/Manager/GameManager.prefab` 에 붙어 있고**, 그 프리팹이 들어간 씬에는
> 자동으로 따라 들어갑니다. 씬 파일에서 스크립트 GUID 만 세면 0 으로 보여 **없는 것처럼 착각합니다.**
> **프리팹 인스턴스까지 세야 합니다.**

| 씬 | PostProcessingController | 경로 |
|----|:---:|---|
| Home | ✅ | GameManager 프리팹 |
| MapScene | ✅ | GameManager 프리팹 + 씬 직접 배치 1개 |
| Shelter | ✅ | GameManager 프리팹 |
| TitleScene | ✅ | GameManager 프리팹 |
| IntroScene / CreditsScene / BadEndingScene | ❌ | 없음 — 셋 다 화면 효과가 필요 없는 씬 |

**즉 이 항목의 남은 일은 "씬에 배치하기"가 아니라 아래 Volume 슬롯 연결입니다.**

그리고 MapScene에 있는 하나조차 Volume 슬롯 4개가 비어 있습니다.

```
Assets/Scenes/MapScene.unity — PostProcessingController
  fantasyVolume:    {fileID: 0}   ← 미연결
  realityVolume:    {fileID: 0}   ← 미연결
  glitchVolume:     {fileID: 716789256}   ✅ 연결됨
  brightnessVolume: {fileID: 0}   ← 미연결
  saturationVolume: {fileID: 0}   ← 미연결
```

#### 미배선 시 증상

이 스크립트는 색맹 모드를 렌더 피처에 전달하는 **유일한 경로**입니다 (`PostProcessingController.cs:97` → `ColorblindRenderFeature.Instance?.SetMode(mode)`).

따라서:
- **타이틀 화면에서 색맹 모드를 켜도 아무 일도 안 일어납니다.** MapScene에 들어가야 비로소 적용됩니다.
- Home·Shelter에서 설정을 바꿔도 즉시 반영 안 됩니다.
- **밝기·채도 슬라이더는 모든 씬에서 무효**입니다 (Volume이 하나도 연결 안 돼 있으므로).
- Play 시작하면 콘솔에 경고가 뜹니다:
  `[PostProcessingController] brightness/saturation Volume이 연결되지 않았습니다.`

#### 작업 절차

**1단계 — Volume 오브젝트 만들기 (MapScene 기준, 한 번만)**

1. MapScene 열기
2. Hierarchy 우클릭 ▸ **Volume ▸ Global Volume** → 이름 `Volume_Brightness`
3. Inspector의 Volume 컴포넌트 ▸ Profile 옆 **New** 버튼 → 프로파일 생성
4. **Add Override ▸ Post-processing ▸ Color Adjustments** 추가
5. Color Adjustments의 **Post Exposure** 체크박스를 켭니다 (값은 0 그대로 두면 됩니다 — 코드가 덮어씁니다)
6. 같은 방식으로 `Volume_Saturation`을 하나 더 만들고, Color Adjustments의 **Saturation** 체크박스를 켭니다

> 밝기용과 채도용을 하나의 Volume으로 합쳐도 동작합니다. 그 경우 두 슬롯에 같은 오브젝트를 넣고, Post Exposure와 Saturation 체크박스를 둘 다 켜세요.

**2단계 — 슬롯 연결**

MapScene의 `PostProcessingController` 오브젝트를 선택하고:

| 슬롯 | 연결할 것 |
|------|----------|
| `brightnessVolume` | `Volume_Brightness` |
| `saturationVolume` | `Volume_Saturation` |
| `fantasyVolume` | (선택) 환상 씬용 Volume — 게이지 연동 색조. 비워도 무해 |
| `realityVolume` | (선택) 현실 씬용 Volume — 게이지 연동 색조. 비워도 무해 |

**3단계 — 다른 씬으로 복제**

MapScene에서 만든 `PostProcessingController` + Volume 2개를 묶어 **프리팹으로 만든 뒤**, 아래 씬에 각각 배치하는 게 관리가 편합니다.

- **Home** — 게임 시작 지점이므로 사실상 필수
- **Shelter** — 플레이 시간이 긴 씬
- **TitleScene** — 설정을 여기서 여는 경우가 많으므로 권장

프리팹 경로 제안: `Assets/Prefabs/Manager/PostProcessing.prefab`

#### 확인 방법

1. TitleScene에서 Play ▸ 설정 ▸ 화면 탭 ▸ **밝기 슬라이더**를 좌우로 → 화면이 밝아지고 어두워짐
2. **채도 강도 슬라이더** → 회색~과채도로 변함
3. 콘솔에 `brightness/saturation Volume이 연결되지 않았습니다` 경고가 **사라졌는지** 확인
4. 접근성 탭 ▸ 색맹 모드를 **타이틀에서** 바꿨을 때 바로 반영되는지

#### 대안 (배치가 번거로울 때)

`PostProcessingController`를 `DontDestroyOnLoad` 싱글톤으로 바꾸면 씬마다 배치할 필요가 없어집니다. 다만 Volume은 씬에 있어야 하므로 완전한 해결은 아니고, 색맹 모드만이라도 전역화하려면 **색맹 전용 드라이버를 분리**하는 게 더 깔끔합니다. 원하시면 🔵 코드 작업으로 처리해 드리겠습니다.

| 필드 | 내용 |
|------|------|
| `panel` | 루트 패널 |
| `choiceGroup` + `talkButton` / `tradeButton` | 대화 / 거래 선택 단계 |
| `tradeGroup` + `slotContainer` | 품목 목록. `GridLayoutGroup` 권장 |

| `offerContainer` + `offerSlotPrefab` | 루의 소지품. **Button + Image(자식) + TMP_Text(개수)** |

> ⚠️ **가격·수치·등급을 표시하는 요소를 만들지 마세요.** 잔액·통화·되판매 개념이 이 게임에 없습니다.
> ℹ️ **아이콘 Image 위치** — 슬롯 프리팹 루트에는 보통 Button의 배경 Image가 있습니다. 코드는 **자식에 있는 Image를 우선**해서 아이콘을 넣고, 자식이 없을 때만 루트를 씁니다. 아이콘을 자식 오브젝트로 두면 배경이 아이콘으로 덮이는 사고가 없습니다.

### 18-B. ⚠ 카메라를 다시 만질 때 알아야 하는 것

**바운드가 화면보다 작으면 카메라가 움직이지 않습니다.** 버그가 아니라 Cinemachine 의 동작입니다.

```
ortho >= theoreticalMax  →  해가 중점 한 점으로 무너져 카메라 고정
```

(`ConfinerOven.cs:265-267` · `:371` `theoreticalMaxCandidate`. `OversizeWindow` 가 꺼져 있을 때)

| 대상 | 바운드(월드) | tmax | 적용 ortho | 결과 |
|---|---|---|---|---|

  `Collider2D.bounds`(월드 AABB)로 재세요.
- 적용할 ortho 는 **`5.625 / N`(N=정수)만** 쓸 수 있습니다(CLAUDE.md §11 줌 절).

**씬 기본 바운드 — 이름 규약 `SceneCameraBounds`**

- `CameraFollow.SetBound(null)` 은 이제 "바운드 없음" 이 아니라 **"방을 나간다"** 는 뜻이고,
  씬 기본 바운드로 되돌아갑니다. 호출자 5곳이 전부 그 뜻입니다.
- 씬 루트에 **이 이름의 GameObject + `BoxCollider2D`(반드시 `isTrigger`)** 를 두면
  씬 로드 때 자동으로 잡힙니다. 인스펙터에 직접 꽂지 않아도 됩니다
  (참조가 씬과 함께 파괴되므로 이름으로 다시 찾습니다).

**Point `Light2D` 반경은 트랜스폼 스케일을 따라가지 않습니다**

`Light2D.GetMatrix()`(URP `Runtime/2D/Light2D.cs:565-573`)가 **Point 타입일 때만**

Freeform·Sprite·Parametric 은 `localToWorldMatrix` 를 쓰므로 영향이 없습니다.
→ 월드 배율을 바꾸면 **Point 라이트 반경은 직접 곱해야 합니다.**

**씬의 뷰포트 `y 0.125 / height 0.75` 는 손으로 넣은 값이 아닙니다**

`PixelPerfectCamera` 는 `[ExecuteInEditMode]` 라 에디터에서도 매 프레임 `Camera.pixelRect` 를

런타임에는 `CameraFollow.LateUpdate` 가 `viewportRect`(0,0,1,1)로 되돌린 뒤 PPC 가 다시 잡으므로

2. `Barrier` 는 **비워 둔다** — 비우면 자기 자신(`결계`)을 쓴다
3. `Player` 도 **비워 둔다** — `Player` 태그로 찾는다
4. `Trigger Distance` 를 씬 뷰에서 맞춘다. 선택하면 **노란 기즈모 원**으로 반경이 보인다

> **왜 콜라이더가 아니라 거리인가.** 정본 `[TRIGGER]` 가 「S#20 종료 후 이동 중 자동 발동」이고
> `[CAM]` 이 「결계에 도달할 때까지 컷을 바꾸지 않는다」이다. 걸어가다 결계가 가까워지면 그대로
> 넘어가는 그림이라, 밟는 순간 켜지는 트리거가 아니라 결계로부터의 거리로 연다.
>
> ⚠ **너무 짧게 주지 말 것.** 결계에 코를 박은 뒤에야 열리면 「도착한다」가 아니라 「부딪힌다」가 된다.
> 기본값 3.5 는 시작값이며, 카메라가 둘을 뒤에서 잡고 있으므로 **결계가 화면에 들어올 즈음**이 맞다.
>
> ⚠ 결계는 **가로로 긴 판**(scale.x 26.9)이다. 거리는 오브젝트의 **원점**에서 재므로 판의 좌우 끝으로
> 접근하면 원점이 멀어 늦게 열린다. 루가 실제로 지나는 길목이 원점 근처인지 확인하고,
> 아니면 길목에 빈 오브젝트를 두고 `Barrier` 에 꽂는다.

### 21-B. 확인 방법 🟡 (3분)

1. `숲 ▸ 결계` 인스펙터에서 **Force Play** 를 쓰거나(디버그용으로 열어 둔 공개 메서드),
   플레이 후 결계 쪽으로 걸어간다
2. 콘솔에 순서대로 뜨면 정상이다. (1)~(6) 이 정본 문단 1259 의 여섯 단계다
   ```
   [S#21] 결계 도달 — 데모 종료 연출 시작
   [S#21] (1) 결계가 눈에 들어온다
   [S#21] (2) 푸른빛을 튕겨낸다
   [S#21] (3) 쿠루가 열쇠를 회수하며 물러난다
   [S#21] (4) 광명이 두꺼워진다 — 필터 환상 강제 · 토글 봉인
   [S#21] (5) 둘이 몇 발자국 물러난다
   [S#21] (6) 루가 천천히 고개를 올려본다
   [S#21] 둘이 돌아본다 — 아무것도 없다
   ```
3. **루가 「아무것도 안 보이는데요」라고 말하는 동안 결계가 보이면 안 된다.** 보이면
   `Barrier Touch` 를 앞 노드에서 켜고 있는 것이다 — 켜는 자리는 `Arrival` 과 `KeyCheck` **사이**다
4. **강화 이후 F 키를 눌러도 현실로 바뀌지 않아야 한다.** 바뀌면 봉인이 안 걸린 것이다
5. 마지막에 검은 화면 + `인형화 00%` 한 줄 → `TitleScene`

### 21-C. 결계 3상태 스프라이트 🔴 (아트 의존)

> ✅ **강화 자체는 아트 없이도 보인다.** 디렉터가 황금 광막을 런타임 캔버스로 그리고
> 카메라 흔들림·글리치·물러섬을 함께 만든다(정본 1259 여섯 단계). 스프라이트는 그 위에
> 얹히는 것이며, 없다고 해서 강화가 안 보이지는 않는다.
>
> ⚠ 광막을 `ScreenEdgeEffectController` 에만 싣지 않은 이유가 있다 — 그 컴포넌트는
> **접근성 설정이 꺼지면 아무것도 하지 않는다.** 거기에만 실으면 설정을 끈 플레이어에게
> 강화가 전혀 전달되지 않는다. 가장자리는 보조 채널로만 함께 쓴다.

슬롯 3개(`Barrier Idle` / `Barrier Touch` / `Barrier Reinforced`)를 비워 두면 그 연출만
건너뛴다. 아트가 나오면 꽂는다. 규격은 **D-3 S#21 신규 에셋**과 F-6-2 를 따른다.

| 상태 | 내용 |
|---|---|
| ① 평상 | 빛으로 된 얇은 판. 황금색이 **언뜻** 비칠 뿐이며 자세히 봐야 안다. 걷는 동안 한 번만 스치고 아무도 반응하지 않는다 |
| ② 접촉 | 쿠루가 열쇠를 댄 **자리 주변만** 드러난다. 세라의 결계 점검(F-6-1)과 같은 원리다. ③과 구분돼야 하므로 범위·지속을 크게 쓰지 않는다. **켜지는 자리는 `Forest_Barrier_Arrival` 과 `Forest_Barrier_KeyCheck` 사이**(정본 문단 1238)이며, 앞 노드에서 켜면 루의 「아무것도 안 보이는데요」와 화면이 어긋난다 |
| ③ 강화 | **전면 가시화.** 이 상태로 데모가 끝난다 |

> ⚠ **카메라 정사영 크기를 바꾸지 않는다.** ③ 이 화면 안쪽으로 밀려오는 것은 스프라이트
> `localPosition` 오프셋(`Reinforced Push In`)으로만 만든다. 줌으로 당기면 픽셀 정수배가 깨진다(F-6 · §11).

### 21-D. SFX 3종 🔴 (4번 AudioManager 선행)

**이름을 지어내지 않았다.** AudioManager 에 실제로 등록한 뒤 그 이름을 인스펙터에 적는다
(CLAUDE.md §4 「이름의 출처」). 비어 있으면 무음으로 넘어간다.

| 필드 | 정본 표기 | 비고 |
|---|---|---|
| `Sfx Owl` | 부엉이 울음 **「후우」** | 대사창을 쓰지 않고 SFX 로 처리한다(F-4-4). **표기는 고정이다.** S#01 의 부엉이 SFX 재활용 가능 여부는 F 에서 확인 중 |
| `Sfx Reinforce` | 결계가 강화되는 소리 | 정본에 표기 없음. 넣을지도 판단 대상 |
| `Sfx Clicking` | **딱딱.** 두 번 | 다시 걷기 시작하는 순간에 맞춘다(C-7-2 숲 후반). 「분노 이후의 당혹감」과 같은 강도이며 **새 강도를 만들지 않는다** |

> ⚠ 부엉이는 **돌아본 자리가 아니라 그 뒤에** 운다. 아무것도 없다는 공백을 먼저 두고,
> 공백이 끝난 다음에 소리가 난다. 디렉터가 그 순서로 돼 있으니 `Empty Beat Duration` 을
> 0 으로 만들지 말 것.

### 21-E. 종료 화면 — 씬을 만들지 않는다 ✅

검은 화면에 `인형화 00%` 한 줄은 **디렉터가 런타임 캔버스로 만든다**(sortingOrder 1000,
`TransitionManager` 암전 999 위). 씬도 프리팹도 필요 없고 Build Settings 도 그대로다.

> ⚠ **`CreditsScene` 을 `Next Scene` 에 넣지 말 것.** 정본 `[UI]` 가 「크레딧을 올리지 않는다」이고,
> `CreditsManager` 는 크레딧을 스크롤한 뒤 결과를 띄우는 화면이라 어긋난다. 기본값은 `TitleScene` 이다.
>
> `Next Scene` 을 **비우면** 종료 화면을 띄운 채 멈춘다. 「종결이 아니라 정지」를 그대로 두고
> 싶을 때의 선택지이며, 그때는 사람이 창을 닫는 것이 데모의 끝이 된다.

### 21-E-2. 강화 연출 수치 🟡 (화면 확인)

정본 1259 의 여섯 단계가 인스펙터 값으로 열려 있다. **화면을 보고 맞추는 것이 맞다** —
아래는 시작값이며 실측으로 정한 값이 아니다.

| 단계 | 필드 | 시작값 |
|---|---|---|
| ① 눈에 들어온다 | `Reveal Alpha` | 0.22 |
| ② 푸른빛을 튕겨낸다 | `Repel Flash Alpha` · `Repel Glitch Duration` · `Repel Shake` | 0.6 · 0.45 · 0.35 |
| ③ 열쇠 회수 | `Recover Slowmo Scale` · `Kuru Step Back` | 0.45 · 0.35 |
| ④ **눈이 부실 만큼** | `Surge Peak Alpha` · `Surge Duration` · `Surge Shake` | 0.92 · 1.6 · 0.6 |
| 잔광 | `Afterglow Alpha` | 0.18 |
| ⑤ 물러섬 | `Pair Step Back` | 0.6 |
| ⑥ 고개 올리기 | `Look Up Delay` | 0.7 |

> ⚠ `Surge Peak Alpha` 가 높아도 되는 것은 **순간**이기 때문이다. 거기서 오래 머물면 안 된다 —
> 두꺼워지는 것은 결계이지 화면이 아니다.
> ⚠ `Afterglow Alpha` 는 이후 대사가 그 위에 뜬다. 너무 높으면 글자가 묻힌다.
> ⚠ **줌을 쓰지 않는다.** 흔들림만 쓴다. 정사영 크기를 바꾸면 픽셀 정수배가 깨진다(§11).

### 21-F. 손대지 말 것 ❗

- **`<<jump>>` 를 노드에 박지 않는다.** 디렉터가 다섯을 순서대로 부르고 사이에 열쇠 접촉·무음·
  강화·돌아보기·부엉이를 끼운다. jump 를 박으면 그 자리가 사라진다
- **노드를 합치지 않는다.** `Arrival` / `KeyCheck` 가 나뉜 것은 그 사이에서 ② 를 켜기 위해서다
- **세라 스프라이트를 세우지 않는다.** 목소리만 나오며 이름도 포트레이트도 띄우지 않는다
  (E-62-4 · F-7-5). 화자 ID `세라목소리` 가 그 처리를 맡는다
- **루가 저항하는 동작을 넣지 않는다.** 필터가 환상으로 덮이는 것을 그대로 둔다. 저항을 넣으면
  루가 상황을 파악한 것이 되어 은폐 축이 무너진다
- **인형화 분기를 만들지 않는다.** E-62-3 에서 폐기됐고 대사는 한 벌이다. 31 을 넘긴 플레이어도
  같은 대사를 보며, 넘긴 결과는 종료 화면의 수치로만 남는다
- **「잠겼다」는 UI 표시를 두지 않는다.** 토글이 그냥 듣지 않을 뿐이다(정본 ▶조작)
