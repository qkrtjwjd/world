### BGM — 시스템이 다릅니다 ⚠️

```
play_bgm  →  Resources.Load<AudioClip>(경로)     ← Resources 폴더 기준
play_sfx  →  AudioManager.sounds 의 등록 이름     ← 완전히 다른 시스템
```

`KitchenTriggerCutscene.bgmMusicBoxName = "music_box"`는 **AudioManager 쪽 이름**이라
`play_bgm "BGM/music_box"`로는 동작하지 않는다. 둘 중 어느 쪽으로 통일할지 아직 미정.

**S#13 신규 BGM** — 문이 열리는 순간부터 아주 조용한 선율 하나. **오르골 계열 음색을 쓰지 말 것**(정본 명시).

`IntroScene` 의 `IntroManager` 가 **자기 CanvasGroup 으로 검은 배경을 만들어** 독백 4줄을
한 글자씩 타이핑해 띄운다(스킵 가능). 그런데 `NightSequenceManager` 도 Home 시작 시
`Opening_Monologue` 노드로 **같은 4줄을 다시** 재생하고 있었다.

두 번째 재생은 방이 다 보이는 상태 위에 떠서 "독백은 검은 화면에 나와야 하는데" 라는
위화감의 원인이었다. → `NightSequenceManager.yarnNode_opening` 기본값을 `""` 로 바꾸고
`Home.unity` 의 값도 비웠다. 노드 자체는 보관.

> ⚠ 이 독백을 Home 안에서 다시 쓰려면 **페이드 오버레이 문제**를 먼저 풀어야 한다.
> `FadeOverlay [Auto]` 캔버스는 `sortingOrder 999` 인데 대사 UI 캔버스는 `0` 이다.
> `<<fade_to_black>>` 을 걸면 대사 글자까지 같이 덮인다(실제로 시도해 확인함).

### 7-2. 목표 UI 가 항상 같은 문구만 띄우고 있었다 ✅ 수정

`Objective Canvas.prefab` 의 `ObjectiveManager` 가 텍스트 참조 3개를 **전부 놓치고 있었다.**

```
objectiveHeaderText: {fileID: 0}
objectiveBodyText:   {fileID: 0}
hudText:             {fileID: 0}
```

`ShowObjective(header, body)` 가 패널만 켜고 글자는 못 썼다. 그래서 yarn·C# 이 무엇을 넘기든
프리팹에 구워진 `"창밖에서 이상한 소리가 들립니다"` / `"목표 : 창문으로 이동해서 밖을..."` /
`"New Text"` 가 그대로 보였다. **게임 전체의 목표 UI 가 다 이랬다.**

→ 세 참조를 실제 TMP(`Objective Panel/header`, `Objective Panel/body`,
`HUD_Objective Panel/Text (Legacy)`)에 연결하고 구워진 플레이스홀더를 비웠다.
수정 후 목표가 `창문으로 이동해서 밖을 확인하세요.` 로 제대로 뜨는 것을 확인했다.

### 7-3. 연출 지시가 대사로 출력되고 있었다 ✅ 수정

`House_Owl_Wake` 첫 줄:

> 오프닝 독백에서 이어지며 어두운 방 안이 서서히 보인다. 달빛만 새어 들어오는 침실.

정본에서는 `▶ 페이드인 …` 으로 시작하는 **연출 지시**다. 2026-08-04 변환 때 `▶` 마커만
떨어지고 설명이 표시 대사로 남았다. 플레이어에게 "오프닝 독백에서 이어지며" 같은 제작 용어가
그대로 보이던 상태. 주석 처리했고, `House_Opening.txt` 에도 `▶` 마커를 복원했다.

정본의 ▶ 지시 55줄을 .yarn 전체와 대조한 결과 **새어 나간 줄은 이것 하나뿐**이었다.
이번에 새로 쓴 13개 노드는 깨끗하다.

### 7-4. 목표 패널이 대사창을 덮고 있었다 ✅ 수정

yarn 의 `<<show_objective>>` 는 **대사 재생 도중에** 실행된다. 목표 패널은 대사창 위에 그려지므로
대사가 통째로 가려졌다. `ObjectiveManager` 는 HUD 만 대사 중 숨기고 있었고(`HideHUD`/`RestoreHUD`),
**큰 목표 패널은 억제 대상이 아니었다.**

→ `_dialogueRunning` 상태를 두고, 대사 중 `ShowObjective()` 호출은 **표시를 미뤘다가
대사 종료 시점에 띄우도록** 바꿨다(저널 기록은 즉시). 이미 떠 있던 패널도 대사 시작 시 접는다.
검증에서 목표가 대사 종료 후에만 뜨는 것을 확인했다.

### 7-5. 카메라가 엉뚱한 방을 비추고 있었다 ✅ 수정

`camera_closeup` 은 `GameObject.Find(이름)` 으로 대상을 찾는데(`CameraDirector.cs:427`),
**같은 이름의 오브젝트가 여러 개면 아무거나 하나**를 잡는다.

| 이름 | 개수 | 있던 곳 |
|------|------|---------|
| `침대` | 3 | 루의 방 · 세라의방 · 유의방 |
| `의자` | 3 | 루의 방 · 세라의방 · 부엌 |
| `창문` | 3 | 루의 방 · 세라의방 · 다락방 |

그래서 밤 씬 시작에서 카메라가 루를 비추다 **다른 방으로 날아갔다가** 돌아오고 있었다.
→ 9개를 전부 고유 이름으로 바꾸고(`루 침대` `부엌 의자` `루 방 창문` 등) yarn 의 대상도 맞췄다.

**`camera_closeup "세라"` 는 제거했다.** 씬의 `세라` 오브젝트는 낮 씬용으로 **정원**에 서 있고
(약 -5.7, 27.9) 밤 씬에서 코드가 위치를 옮기지 않는다. 정본이 요구하는 "문틈 사이 세라의 눈
클로즈업" 은 바로 아래 `showSprite "세라" "door_gap"` 이 담당한다.

> ⚠ **앞으로 `camera_closeup` 대상을 정할 때는 씬에 그 이름이 하나뿐인지 반드시 확인할 것.**
> 못 찾으면 조용히 플레이어로 폴백하고, 여러 개면 조용히 엉뚱한 걸 잡는다. 둘 다 에러가 안 난다.
